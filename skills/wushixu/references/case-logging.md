# 案例沉淀规则（每次 wushixu 调用必做）

> 用户约定（2026-06-26）：所有 /wushixu 分析都沉淀为 case，方便后续复盘。
> 双重价值：复盘个人决策 + 检验理论（框架准不准、边界在哪），同 `case/07`。

## 何时落

每次完成一次 wushixu 分析（给出三道目光 + 判断 + 建议）后，都落一份 case。哪怕结论是「框架使不上力」，也记一句——那是对边界的记录。

## 落哪

- 目录：`13-物势序论/case/NN-<短名>/README.md`，NN 续现有最大编号（07 之后从 08 起）。
- 登记：在 `13-物势序论/case/README.md` 的目录表加一行（编号、案例、类型、一句话、锚/回看时点）。
- 类型标注：`后验`（历史已知）/ `LIVE`（事前预测，研判类）/ `应用`（决策/诊断/复盘类，软回看）。

## 模板

```markdown
# NN · <标题> —— <类型：LIVE 预测 / 应用决策 / 困局诊断 / 复盘>

| 字段 | 值 |
|---|---|
| 场景 | 困局诊断 / 决策与介入 / 趋势研判 / 现象解释·复盘 |
| 立档 | YYYY-MM-DD |
| 回看 | YYYY-MM-DD（研判=硬回看；其它=软回看节点） |

## 问题
<用户的原始处境，可脱敏>

## 三道目光
物 / 势 / 序

## 核心判断
<按场景：断点 / 下手点 / 真势vs虚热 / 结构>

## 建议
<补物/借势/造序，或决策六步要点>

## 可证伪点 / 回看条件
- 研判类：可证伪预测（带主观概率）+ 证伪条件
- 应用类：到回看时点，看什么算「判对了 / 方案立住了」

## 回看记录（到点填，事前留空）
- [ ] ……
```

## 纪律

- 涉隐私的私人事务：正文脱敏，存档为复盘、不为公开。
- 研判类务必锁时间戳 + 回看时点（破后验 / 确认偏误，见 07）。
- 不臆造回看结论；没到点就留空。
- 若日后私人事务太多、稀释理论验证案例，可在 `case/` 下分子目录区分「理论验证级」与「个人应用级」（届时再议）。
